Academic Smart Hub — Dashboard Specification & Development Plan

Prepared By: Mr. Bishnu Singh Rayamajhi · Mathematics Lecturer and Head, Department of Humanities and Social Sciences · Kapilvastu Multiple Campus, Taulihawa, Nepal, For KMC-HSSD & All Academic Researchers · 11 October 2026

The Academic Smart Hub is one bilingual (English/Nepali) dashboard from which Mr. Rayamajhi runs teaching, student submissions, research supervision, content publishing and announcements. It replaces switching between Google Docs, Forms, Sheets, GitHub pages, YouTube, Facebook and LinkedIn with a single workspace for the Department of Humanities and Social Sciences at Kapilvastu Multiple Campus.

Purpose and vision

Today the department's work is spread across many tools that were each built well but do not talk to each other. The Hub connects them without replacing them: every Google Form, Sheet, video and page stays where it is, and the Hub becomes the place that knows about all of it.

Goals

  • Find any academic resource in under 10 seconds from one searchable hub.
  • See submission and evaluation status for every assignment without opening each response sheet.
  • Follow each student research project from idea to completion.
  • Plan, publish and share content and announcements from one place.
  • Work equally well on a phone in Taulihawa and a laptop on campus.
  • Keep all data in Mr. Rayamajhi's own Google account, with no paid server.

Architecture

The system has no server of its own: a single HTML file talks to your Apps Script, and only the script can touch your Sheet.

Architecture · 3 layers, 2 data sources

The dashboard sends every request with the secret token. The script checks it, then reads or writes the five data tabs and counts rows in the Form response sheets. The social platforms are reached through links and share buttons, not through the script.

Data model

All data lives in one Google Sheet with five tabs, one per collection, so it can be read, filtered and corrected by hand as well as through the dashboard.

TabColumnsNotes
linksid, title, url, type, note, pinned, updatedtype is one of docs, forms, sheets, html, website, youtube, facebook, linkedin, other

announcementsid, title, body, link, datelink is the page or video the announcement points to

Live counting rule: submitted is the number of non-empty response rows; evaluated is the number of rows where the Marks column (name configurable) is filled. Dates are stored as plain text (YYYY-MM-DD) so Sheets does not reformat them.

Interface and experience

The interface is mobile-first, because most daily checks happen on a phone, and follows the dark theme with gold and orange accents used across your other apps.

  • Navigation: a left sidebar on laptops and a bottom bar on phones, with the same eight sections: Overview, Platform Hub, Assignments, Research, Content, Announce, Sync, Setup.
  • Language: one tap switches every label between English and Nepali; content you type stays as written.
  • Theme: dark by default, with a light option for bright rooms.
  • Speed: a single HTML file with no build step, so it opens quickly on a weak connection and can be uploaded to GitHub Pages like your other apps.
  • Clarity: each action uses one consistent verb (Add, Edit, Delete, Save, Open, Copy), and empty screens say what to add first.
  • Accessibility: visible keyboard focus, readable contrast in both themes, and reduced motion respected.

Security and privacy

The main protection is that data stays in your own Google account and the backend rejects any request without your secret token.

  • Token: a long random secret is set in the Apps Script and typed once into the dashboard. It is stored only in your browser and is excluded from backups.
  • Public file, private data: the dashboard HTML contains no links, tokens or student data, so hosting it publicly on GitHub Pages is safe.
  • Web app access: the Apps Script must be deployed as accessible to anyone so the page can reach it; the token is what blocks strangers. Use a long token and change it if it is ever shared.
  • Student data: names and marks stay in Google Form response sheets, shared only with people you choose. Do not paste student personal data into announcements.
  • Backups: download a JSON backup regularly; Google Sheets version history is the second safety net.
  • Permissions: the script asks only to read and write your spreadsheets. Review them when approving.
  • Compliance note: if the campus has rules on storing student records, confirm them before adding marks views (planned Phase 3).

Development plan

The work runs in four phases, and each phase starts only when the gate before it is met.

Roadmap · 4 phases, 3 gates

Phases 1 and 2 are finished in the Academic Command Center. Phase 3 needs real response sheets with a Marks column to test against. Phase 4 starts only after you decide to apply for the Facebook and LinkedIn access it depends on.

Success measures and next steps

The Hub succeeds if you can run a normal week from it without opening the individual tools first.

Measures

  • Every active Form, Sheet, Doc, repository and social page is listed in the Platform Hub.
  • Each current assignment shows live submitted and evaluated counts.
  • Every research project has a current stage.
  • Announcements go out from the Hub for one full month.

Next steps

Facebook and LinkedIn approval requirements are approximate and should be checked against each platform's current developer terms before applying.
